# Приёмочные испытания облачной Beta

## Границы этой сборки

Это тестовая сборка компонентов облака, НЕ готовая автоматическая синхронизация. Не выдавать ключи с Allow write access. Не использовать реальные личные данные для испытаний. Тесты на двух временных базах не переключают основную Room.

## Порядок проверки

1. Установить новую Beta поверх текущей. Проверить, что список, архив, база товаров, магазины и локальный профиль сохранились. Создать локальный .buylist до проверки.
2. Профиль → Облачное хранилище → Помощь с подключением → Самопроверка облака. Ожидаются семь OK: изоляция, подписи, слияние, перезапуск журнала/повтор, количество/удаление, права, архив. Повторить запуск.
3. Семь быстрых нажатий по версии внизу профиля: пункт администрации должен появиться и остаться после перезапуска. Проверить скрытие и повторное включение, затем ручной вход, сохранение токена, блокировку при уходе в фон, биометрию/PIN. Неверный/отозванный PAT не должен авторизоваться.
4. В app-cloud проверить приватность и отключённые Actions. Создать тестового пользователя и группу. Проверить роли, передачу владения, архивирование и восстановление.
5. На втором телефоне открыть QR, на первом сканировать. Сверить полный отпечаток, выбрать пользователя. Повторить регистрацию: должна быть отклонена. Отозвать запись. SSH-доступ этим не выдаётся.
6. Сохранить .blcloud с отдельной парольной фразой. Неверный пароль и копия с устаревшим SHA должны отклоняться. Перенос актуальной копии на другой телефон меняет ключ реестра; не делать без тестовых данных и отдельной копии.
7. Проверить ручную копию покупок на тестовых данных. Восстановление с предпросмотром, отказом и подтверждением. Не выполнять с реальными покупками без локальной резервной копии.
8. На втором телефоне создать отдельный тестовый SSH-ключ, скопировать публичный ключ в Settings → Deploy keys репозитория app-cloud. Allow write access оставить выключенным. Проверить 443 и 22. Удалить ключ после проверки.
9. Записать версию APK, Android, результат каждой проверки и точный текст ошибки. Не публиковать PAT, парольные фразы, приватные ключи и содержимое покупок.

## Блокирующие условия для production

- Реальное подключение устройств, доставка подписанного разрешения и ключей, ротация при отзыве.
- SSH fetch/push с безопасным повтором и durable outbox; проверка конкурирующих записей двух устройств.
- Изоляция рабочих пространств в основных экранах, виджете и Bluetooth, явный перенос старых данных.
- Фоновый планировщик и тесты offline/reconnect, потери сети и конфликтов, проверяемый checkpoint при смене epoch.
- Интеграционные тесты CI и испытания на реальных устройствах должны пройти до включения автоматического обмена.

Автоматический обмен в данной сборке отключён.

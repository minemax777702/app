# Несколько каталогов, магазины и история фактических цен

**Ветка:** `feat/multi-catalog-stores-prices` — черновой PR #8, базовая ветка `ui/polish-barcode-card`.

## Архитектура

- В одной Room БД остаются независимые каталоги `lenta_products` и `custom_products`.
- Свои товары имеют UUID и любое число подтверждённых штрихкодов в `custom_product_barcodes` (включая отметки удаления для синхронизации).
- `sharedCatalogIdentities` вычисляет общий канонический ключ по живым штрихкодам: две карточки Ленты не объединяются автоматически, в неоднозначных случаях связь отклоняется. Удаление связывающего штрихкода разъединяет карточки.
- Физические записи каталогов и исторические события НЕ перезаписываются при связывании; ссылки устойчивы при синхронизации через сами штрихкоды.
- Справочник `stores` хранит магазины. Новые ID детерминированы по нормализованному названию; магазин у покупки необязателен.
- `custom_products.estimatedPriceKopecks` хранит необязательную **ориентировочную** цену собственного товара. Она не является историческим расходом и не учитывается в статистике до подтверждения фактической покупки.
- Фактическая цена в копейках сохраняется в `PurchaseEvent`. Отсутствующая цена не включается в денежную статистику, но покупка учитывается по количеству.
- Исправление цены/магазина сохраняет ID и дату покупки, а метка `revisedAt` помогает выбрать последнюю исправленную запись при QR-обмене.

## Миграция и синхронизация

- Room `19→20`: `custom_products`, `stores`, `items.customProductId`.
- Room `20→21`: `custom_product_barcodes`, перенос существующего `custom_products.barcode` с сохранением записей и истории.
- Room `21→22`: nullable `custom_products.estimatedPriceKopecks`; старые товары получают `null`, история покупок не меняется.
- `Snapshot` включает собственные товары, магазины и штрихкоды, синхронизация `SyncCodec v11`; старые форматы декодируются. Старые телефоны с v8/v9/v10 **не читают новые QR v11**; обновить оба устройства перед обменом.
- Схемы `20.json` и `21.json` сохранять. Новую схему `22.json` взять из настоящего KSP-вывода и закоммитить, не изменяя `identityHash` вручную.
- Созданные в разных каталогах товары объединяются как единая логическая карточка по штрихкодам, а не путём разрушительного переписывания двух таблиц.

## Весовые собственные товары — дополнение

- Тип товара: «Штучный» или «Весовой», меняется при создании и редактировании.
- Для весового товара вводится цена **за 1 кг**, при покупке — фактический вес в кг (в базе целое количество граммов).
- Цена и магазин при покупке необязательные, длинное пояснение про покупки без цены убрано.
- `purchaseEvent` всегда сохраняет `weightGrams` даже при ручном `priceOverride`; сумма округляется до копеек через `priceForWeight`.
- Room `22→23`: булев столбец `custom_products.isWeighted` с `DEFAULT 0`, существующие товары остаются штучными.
- SyncCodec `v12`: флаг веса после цены товара, старые v11-снимки читаются с `isWeighted=false`.
- Сгенерировать и закоммитить реальную `app/schemas/com.mok.buylist.data.AppDatabase/23.json` из KSP. Схемы 20–22 сохранить.
- Проверить на устройстве покупку по сканированию, вес 0,750 кг × 329,99 ₽/кг = 247,49 ₽, досрочный архив и QR между обновлёнными устройствами v12.

## Выбор магазина и подстановка цены

- Используется уже существующая `stores` Room-таблица: новый файл БД и миграция не требуются.
- Во всех формах покупки и при редактировании истории вместо свободного поля магазина — `StoreSelectField`: «Без магазина», сохранённые магазины, «Добавить магазин».
- Создание нового магазина — отдельное действие. Магазины синхронизируются через существующий `Snapshot.stores` и протокол v12.
- По выбранному магазину последняя фактическая цена ищется по подтверждённым `PurchaseEvent` в текущих и архивных покупках с учётом связанных по штрихкоду карточек Ленты и пользовательского каталога.
- Подставляется **цена единицы** (или **цена за килограмм** весового товара), а не общая стоимость чека.
- Если в выбранном магазине цены ещё не было, используется исходная ориентировочная цена собственного товара либо пустое поле; пользователь может ввести любую фактическую стоимость.
- Смена магазина не должна подмешивать цену предыдущего магазина. Асинхронный поиск не перезаписывает вручную отредактированную сумму.
- При исправлении истории поиск исключает саму редактируемую покупку.
- Юнит-тест: `StorePriceHistoryTest`, включая несколько магазинов, покупки без цены, разные товарные источники, вес и редактирование.

## Единая база товаров и магазинов — ревизия v24

- Единый раздел **«Товары и магазины»** вместо отдельных верхних вкладок «База продуктов» и «Магазины», с переключателем внутри раздела.
- **Лента**: покупка товара из текущего списка одним нажатием, без подтверждения цены или магазина; магазин и известная цена сохраняются автоматически. Сканирование продолжает учитывать особый сценарий весовых штрихкодов.
- **Собственный товар**: подробности из списка показывают тип, все действующие штрихкоды, ориентировочную цену, связанные магазины и последние известные цены, без кнопки обновления цены Ленты.
- Room **23→24**: таблица `store_products` с составным PK `(storeId,productKey)`, необязательной ценой за единицу/кг, временем изменения и флагом удаления. Привязка не удаляет товар из общего каталога.
- В магазине можно найти товар из общего каталога, добавить его, задать/изменить цену, убрать привязку; товары без покупок также отображаются. Товары Ленты в системном магазине выводятся автоматически.
- В карточках общей базы отображаются привязанные магазины с ценами; покупка остаётся отдельной записью в `PurchaseEvent`.
- При покупке в выбранном магазине приоритет имеет явная цена `store_products`, затем последняя цена покупки; ввод фактической цены остаётся редактируемым.
- Синхронизация **v13** передаёт `storeProducts` при обмене списком и архивом; конфликт разрешается по `updatedAt` с приоритетом удаления при равенстве, старые форматы продолжают читаться.
- Старые устройства, поддерживающие только v12, не могут читать исходящие снимки v13 — перед двусторонним QR-обменом обновить оба устройства.
- Добавить сгенерированную KSP-схему `app/schemas/com.mok.buylist.data.AppDatabase/24.json`; схемы 20–23 сохранить. CI на GitHub использует временный SDK 36, исходный `compileSdk = 37` не менять.
- На телефоне проверить добавление товара в магазин до первой покупки, изменение независимых цен двух магазинов, покупку Ленты одним нажатием, подробности собственного товара, архив, удаление и восстановление связи через синхронизацию.

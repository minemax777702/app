# Автоматический редактируемый FIG

Исходный макет: design/source.fig. Ветка beta. Не использовать сгенерированный макет как источник.

После полного захвата обеих тем job ui-handoff создаёт артефакт shopping-list-fig. Внутри Shopping-list-latest.fig и JSON. Новые страницы содержат нативные FRAME, TEXT и VECTOR, без растровых заливок. Исходные узлы и блобы сохраняются; старый растровый генератор остаётся только как вспомогательный модуль декодирования и не вызывается в CI.

Текст извлекается из Android XML, геометрия и цвета оцениваются по скриншотам, векторные контуры создаются с редактируемой сетью вершин. Размер и начертание шрифта оценочные. Отчёт содержит нераспознанные текстовые элементы. Это промежуточная послойная реконструкция, не доказательство pixel-perfect и не семантическая реконструкция всех Compose-компонентов. Без подтверждённого импорта Figma и сравнения рендера точность не заявляется.

Далее требуется экспорт реальных измеренных стилей, семантических контейнеров и исходных drawable из Compose вместо трассировки, и проверка визуальных различий. Сборка FIG не использует PNG в качестве слоя; PNG остаются только в отдельном ui-handoff.

Локально: python3 scripts/update-editable-fig.py --source design/source.fig --handoff ui-handoff --output design-output/Shopping-list-latest.fig (numpy 2.2.6, opencv-python-headless 4.12.0.88, libzstd.so.1).

## Фактические измерения Compose

Вариант uiCapture экспортирует `*.layout.json` для каждого состояния: измеренные границы и положение текста, размеры шрифта в физических пикселях, насыщенность, межстрочный и межбуквенный интервалы, цвет, базовые линии. XML используется для выбора видимого текста; генератор не подбирает размер шрифта по PNG. Координаты переводятся в dp по плотности устройства. Не сопоставленные элементы явно отмечаются в отчёте; точность рендера в Figma и нативные карточки/Auto Layout пока не подтверждены. Экспортёр доступен только в тестовом APK через защищённый DUMP receiver. PNG по-прежнему используются для векторизации нетекстовой графики.

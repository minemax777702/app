# Правила работы над проектом

- Перед работой по ТЗ прочитать `TZ_SHOPPING_APP_CODEX.md`, `CODEX_PROGRESS.md`, `CODEX_HANDOFF.md`, проверить состояние Git и фактический код.
- Выполнять только текущий этап в порядке 01–10; обновлять журнал и передачу после существенных изменений и перед завершением сеанса.
- Сборку и ограничения проверки выполнять с учётом `CLAUDE.md`; интерфейс и комментарии — на русском.

## UI/UX

- При анализе и изменении Android-интерфейса изучать `.agents/skills/mobile-android-design/SKILL.md`, `.agents/skills/mobile-ui-ux-designer/SKILL.md` и `.agents/skills/ui-android/SKILL.md`, применяя рекомендации с учётом задачи и правил пользователя.
- `ui-android` ориентирован на API 34+, тогда как проект поддерживает API 29+. Не повышать minSdk и не менять тему, зависимости или дизайн-систему только ради требований скилла. Для аудита применять его как чеклист без генерации кода и без этапа утверждения дизайна.

## Pixso — источник дизайна

- Для любой задачи изменения UI, макета, синхронизации или проверки Pixso обязательно использовать `.agents/skills/buylist-pixso-sync/SKILL.md`. Скилл определяет полный цикл Kotlin ↔ Pixso, включая CI и критерии завершения; отдельное указание пользователя на синхронизацию не требуется.

- Перед изменением интерфейса прочитать `design/PIXSO_SYNC.md`, `design/pixso-sync.json` (schema 2) и соответствующие реальные фреймы Pixso. Файл: https://pixso.net/app/design/4T8MYI6qqkQjlqe3MKJY7Q?icon_type=1.
- Работать с `targets` и существующими frame_id, а не создавать экран для каждого захвата. Обе темы используют общие слои, варианты компонентов и переменные Theme/* коллекции 01 / Semantic color. Не восстанавливать удалённые архивные страницы и не использовать design/source.fig как рабочий источник.
- При добавлении нового UI сначала определить существующий компонент/вариант либо внести его в Pixso, затем реализовать соответствующий Compose UI. Сохранять бизнес-логику, доступность, динамические данные и состояния приложения.
- CI синхронизирует сопоставленные цвета двусторонне, но останавливается при конфликтующих правках или неизвестной структуре. Структурные правки переносить по актуальному макету с визуальной проверкой; не заменять экран скриншотом или автоматически сгенерированной копией.
- После проверки реализации запускать Pixso bidirectional sync с accept_structure=true только для принятия проверенной структурной базы (это не status=verified). При необходимости включить release для подписанной beta-сборки. Не публиковать stable из этого процесса.
